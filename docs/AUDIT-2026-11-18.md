## ۲. بحرانی (Critical) — قبل از هر چیز

### C1. BFF استودیو کلید ادمین را به هر درخواستی می‌چسباند — [از کد]
`apps/web/src/app/api/studio/[...path]/route.ts` روی **هر** درخواست `X-API-Key: STUDIO_API_KEY` می‌گذارد، بدون هیچ لاگینی.
- هر کسی که به پورت `3000` دسترسی دارد = ادمین کامل control plane (introspect هر DB، activate، ساخت API key، خواندن DB URL با پسورد، git browser).
- چون backend اول API key را چک می‌کند، **OIDC عملاً دور زده می‌شود**.
- CSRF: endpointهای POST بدون body (`/studio/deactivate`، `/specs/{n}/history/{id}/restore`) از هر سایتی با یک form قابل‌فراخوانی‌اند.
- `/api/data/*` هم کلید data را تزریق می‌کند ← data plane از طریق وب باز است.

### C2. `/auth/token` بدون احراز هویت، توکن با هر نقش و claim می‌سازد — [تأیید‌شده]
`data_api_builder.py:307` — در حالت `auth: jwt`، `POST /auth/token {"roles":["admin"],"tenant":"B","exp":4102444800}` توکن معتبر با نقش admin، claim دلخواه (row-level) و حتی `exp` سال ۲۱۰۰ برمی‌گرداند (`extra` روی claimهای سیستمی overwrite می‌شود). یعنی **کل JWT/RBAC/row-level بی‌اثر است**.

### C3. GraphQL نقش و claim را از آرگومان کلاینت می‌خواند — [تأیید‌شده]
`graphql_facade.py` — `endpoint(name:"docs", roles:["admin"], claims:{tenant:"B"})` به یک viewer از tenant A، ردیف‌های tenant B با فیلد مخفی `salary` را داد. علاوه بر این mutationها:
row-level را اعمال نمی‌کنند (update/delete ردیف tenant دیگر)، `endpoint.roles`، validations، audit، webhooks، invalidate کش و idempotency را دور می‌زنند.

### C4. کش پاسخ بین tenantها و بین APIها نشت می‌کند — [تأیید‌شده]
- کلید کش (`ep:{name}:list:{query}:fields=…`) principal/claim را ندارد ← با `row_level`، tenant B داده‌های کش‌شدهٔ tenant A را دید.
- کلید کش با نام API namespace نشده ← در multi-active، `GET /items/1` روی API-B داده‌های API-A (دیتابیس دیگر) را برگرداند.
- کش به‌صورت پیش‌فرض **روشن** است (`CacheConfig.enabled=True`).

### C5. Fail-open در پیش‌فرض‌ها — [تأیید‌شده/از کد]
- `auth: api_key` (پیش‌فرض spec) وقتی `DATA_API_KEYS` خالی و کلید managed نیست ← **بدون کلید 200** (تأیید‌شده).
- `STUDIO_API_KEY` و `JWT_SECRET` مقدار پیش‌فرض شناخته‌شده دارند و در `environment=production` هیچ گاردی برای رد کردنشان نیست؛ docker-compose هم همین پیش‌فرض‌ها را می‌گذارد.

## ۴. متوسط (Medium)

- **M1 ETag/If-Match خراب** — ETag در GET روی نمایش projected (با relations/RBAC/sparse) حساب می‌شود ولی در PATCH روی ردیف کامل ← با relations، If-Match تازه همیشه `412`. [تأیید‌شده]
- **M2 Relations** — همهٔ فرزندها fetch و بعد در پایتون به `max_per_parent` بریده می‌شوند (بدون LIMIT ← DoS روی جداول بزرگ)؛ soft-delete/row-level روی جدول فرزند اعمال نمی‌شود؛ detail پارامتر `include` را نادیده می‌گیرد. [از کد]
- **M3 نشت engine/connection pool** — `create_data_app` در preview-openapi، export، diff-specs و هر rebuild در multi-active یک engine جدید می‌سازد و dispose نمی‌کند؛ `handle_insert` در worker هم برای هر جاب engine جدید. [از کد]
- **M4 SQL endpoints** — پارامتر تایپی غلط (`?min=abc`) ← 500 [تأیید‌شده]؛ SQL در تراکنش `READ ONLY` اجرا نمی‌شود و فقط blacklist کلمات دارد (توابع side-effect دار Postgres مثل `pg_terminate_backend`، `nextval`، `FOR UPDATE` رد نمی‌شوند)؛ soft alias `field_op` و `?q=` برای SQL endpoint پشتیبانی نمی‌شود (ناسازگار با جدول‌ها).
- **M5 محدودیت حجم body** فقط روی `Content-Length` است ← درخواست chunked محدودیت ندارد. [از کد]
- **M6 Rate limit و KV** — in-memory و per-process؛ همهٔ کلاینت‌های anonymous یک bucket مشترک دارند (یک نفر همه را 429 می‌کند)؛ `MemoryKv` هیچ eviction ندارد ← با query stringهای متنوع حافظه بی‌نهایت رشد می‌کند. [از کد]
- **M7 Idempotency** — get/put اتمیک نیست (دو درخواست هم‌زمان هر دو اجرا می‌شوند)؛ کلید با principal و API scope نشده. [از کد]
- **M8 OIDC** — بدون nonce و PKCE؛ اگر `STUDIO_OIDC_AUDIENCE` خالی و allowlist خالی باشد، **هر توکن معتبر از آن issuer** (مثلاً هر حساب گوگل) ادمین استودیو است؛ `return_to="//evil.com"` وقتی `post_login_url` خالی باشد open redirect. [از کد]
- **M9 Webhooks** — بدون محافظت SSRF؛ یک thread به‌ازای هر رویداد × هر hook. [از کد]
- **M10 Jobs** — `/jobs/{id}` برای هر principal احراز‌شده از هر API باز است و ردیف کامل را برمی‌گرداند؛ دیکشنری `_jobs` درون‌پردازه‌ای هیچ‌وقت پاک نمی‌شود. [از کد]
- **M11 نشت جزئیات خطا** — `str(exc)` در `database-unreachable`، `sql-preview-failed`، `relation-error`، bulk؛ `/specs/{n}/openapi` خطا را با فرمت غیر-Problem-Details برمی‌گرداند. [از کد]
- **M12 فیلتر روی فیلد مخفی RBAC** — `allowed_fields` با RBAC اشتراک گرفته نمی‌شود، پس viewer می‌تواند با `salary__gt=` مقدار فیلد مخفی را استنتاج کند (فعلاً به‌خاطر H1 روی ستون عددی 500 می‌دهد، روی ستون متنی کار می‌کند). [از کد]

## ۵. کم (Low) / استاندارد API

- `PUT` دقیقاً مثل `PATCH` (partial) رفتار می‌کند؛ `201` هدر `Location` ندارد.
- `/studio/token` از `JwtConfig()` پیش‌فرض استفاده می‌کند نه jwt config خود spec ← توکن برای spec با issuer/audience سفارشی کار نمی‌کند.
- snapshot تاریخچه با دقت ثانیه نام‌گذاری می‌شود ← دو save در یک ثانیه همدیگر را overwrite می‌کنند.
- خطای mount کردن GraphQL با `except Exception: pass` بی‌صدا بلعیده می‌شود.
- نام در `/studio/activate/{name}` اعتبارسنجی نمی‌شود (برخلاف `spec_repo._safe_name`).
- پیش‌فرض `AppConfig.api_prefix="/v1"` ولی Studio و CHANGELOG می‌گویند پیش‌فرض خالی است.
- CORS هدرهای `If-Match`/`If-None-Match` را allow و `ETag`/`Link` را expose نمی‌کند ← کلاینت مرورگری نمی‌تواند از ETag و pagination link استفاده کند.
- `_ensure_trace` کد مرده دارد؛ `X-Trace-Id` ورودی بدون اعتبارسنجی لاگ می‌شود.
